# 投稿操作プラグインのアイデアと初期案

配布、実行権限、作者向け API と実装順は [プラグインの配布と実行](plugins/runtime.md) で定める。以下の API 例は検討時の案。

SNS のログイン・閲覧・投稿が揃った後、投稿メニューを最初の拡張箇所とする。初期状態ではすべて無効。まず同梱の任意プラグインで操作の契約を試す。第三者コードを読み込む仕組みは、権限と隔離の設計が必要になるため別途検討する。

最初の候補は「投稿を翻訳」。有効にすると投稿メニューに現れ、選んだ投稿の本文と翻訳先の言語を受け取る。翻訳結果は原文の下に表示する。利用者が取り消した場合や別の投稿へ移った場合は結果を破棄する。

[Sakutto](https://github.com/jammaru/sakutto) はブラウザ拡張内で wllama を使い、PLaMo を WebGPU または CPU で実行している。Flare では通常の PWA での動作を試す。初回のモデル取得前に容量を示し、利用者が選んだ端末に保存する。無効時の初期通信、モデル取得の中断と再開、Android ブラウザでのメモリ使用量と翻訳時間を確認してから採用を決める。

## 基本機能が揃った後に試す候補

| 候補 | 使う場面と操作 | 必要なデータ |
| --- | --- | --- |
| Markdown で引用 | 読書メモに残したい投稿を選び、本文・著者・元リンクを引用形式でコピーする。投稿メニューとクリップボードだけで最初の拡張を試せる。 | 選んだ投稿と元リンク |
| あとで検索するための私的メモ | 保存した投稿に「この配色を参考にする」など一言を添え、あとからその言葉で絞り込む。 | 投稿の識別子と端末内のメモ |
| 同じリンクをまとめる | 複数の SNS で同じ記事が流れてきたとき、同一 URL を含む投稿をまとめる。展開すると各人のコメントを読める。 | 読み込み済みの投稿に含まれるリンク |
| 読み上げ | 長い投稿をメニューから読み上げる。原文と翻訳文がある場合は読む方を選べる。 | 選んだ本文と言語、端末の音声 |

## 作者が最初の操作を作るまで

Misskey は投稿、ユーザー、投稿フォームに対応する操作を別々に登録できる。Flare の最初の拡張箇所は投稿メニュー一つに絞る。公開する入力は SNS 間で共通の投稿本文、著者名、元リンクとする。作者が SNS ごとのデータ構造を調べずに済む。[Misskey Plugin API](https://misskey-hub.net/en/docs/for-developers/plugin/plugin-api-reference/)

Joplin では雛形に manifest と小さな動作例が入り、開発用プロファイルで試せる。Flare でも作者が実アカウントを用意する前に、サンプル投稿で動作を確認できるプレビューを用意したい。[Joplin の開発ガイド](https://joplinapp.org/help/api/get_started/plugins/)

次は提案段階の作者用インターフェース。最初の作例は素の JavaScript と JSON の二つのファイルで完結し、ビルドも Flare 本体の改変も不要とする。

```json
{
  "id": "example.quote",
  "apiVersion": 1,
  "version": "0.1.0",
  "postActions": [{
    "id": "quote",
    "label": { "en": "Copy quote", "ja": "引用をコピー", "zh": "复制引用" },
    "entry": "./quote.js"
  }]
}
```

```js
// quote.js
export default function run({ post }) {
  const quote = post.text.split("\n").map(line => "> " + line).join("\n");
  return { kind: "copyText", text: quote + "\n\n" + post.url };
}
```

本体がラベルを表示し、利用者が選んだときにだけ操作を起動する。本体は結果の種類とサイズを検証し、コピーできない環境では選択可能なテキストを表示する。翻訳の場合は結果を投稿の下に表示し、入力には利用者が選んだ翻訳先言語を加える。

インストールした版は無効状態から始める。無効化・ログアウト時には実行を止め、前の実行から遅れて届いた結果を捨てる。同じ投稿が二つの接続アカウントに現れた場合も、結果は操作を開始したカードにだけ戻す。未対応の API バージョンは読み込む前に表示する。

第三者配布の前に、別オリジンの隔離環境とメッセージ経由の呼び出しを試作する。本体 DOM・認証済み API・ブラウザストレージ・外部通信への直接アクセスを制限できることを実ブラウザで確認する。モデル取得は、利用者が容量と配布元を確認して開始できる本体側の操作として検討する。最初の作者テストは「雛形をコピーし、文字列を変え、プレビューで結果を確認する」までを第三者が本体のソースを開かず完了できるかで判断する。

## Flare で先に試したい三つの体験

### 遠征タブ

ライブやカンファレンスの前に「東京公演、日曜日まで」のような期間限定タブを作る。X では公式アカウント、Misskey では現地のハッシュタグ、Bluesky では知り合いのリストを選び、当日だけ同じタイムラインで追う。会期が終わるとタブは閉じ、スターを付けた投稿だけが読み返せる。最初の試作は、既存の検索・リストを束ねる機能と有効期限に絞る。保存と閉じる処理は端末内で完結する。

### その後を追う

「いまこのアプリを作っている」という投稿を見つけたら、投稿メニューから「続報を追う」を選ぶ。同じ作者が同じスレッドに追記したとき、元の投稿と並べて「その後」に表示する。最初の試作は明示的な返信関係だけを対象にする。別の SNS にある続報は利用者がリンクして追加できる。名前の一致だけで人物を結び付けない。

### クロスポストの楽屋

一つの下書きを複数の SNS に出す直前、送信先の数だけプレビューを並べる。例えば Mastodon にだけ内容注意を付け、Bluesky は文字数に収まるよう末尾を短くし、Nostr は原文のままにする。変更した箇所と送信先を本体の確認画面に戻し、送信の判断は利用者が行う。最初の試作は本文の個別編集と差分表示。各 SNS に固有の項目は本体側の投稿対応に合わせて追加する。

遠征タブにはタイムライン、続報には投稿メニュー、楽屋には投稿画面という異なる拡張箇所が必要になる。最初に続報の最小版を作れば、投稿操作の設計を実際の利用で評価できる。他の二案はその結果を見てから拡張 API に反映する。

## Twitter 周辺のツールから考える候補

- **別の SNS で開く**。プロフィールに著者自身が載せている別アカウントを候補にし、Flare 内で移動する。FediFinder が Twitter のフォロー先のプロフィールから Fediverse のアドレスを探す発想を、一人ずつ読む操作に応用する。[FediFinder](https://github.com/lucahammer/fedifinder)
- **このタブの読み方**。Control Panel for Twitter のタイムライン調整をヒントに、タブごとに「本人の投稿」「人から回ってきた投稿」を切り替える。後者を選ぶと、誰の紹介で見つけたかを投稿の上に表示する。[Control Panel for Twitter](https://github.com/insin/control-panel-for-twitter)

WebMCP は同梱の任意プラグインとして検索フォームに接続する。設定で有効にし、Discover を開いたときだけ、対応ブラウザが flare_search_posts を発見できる。検索の送信先と結果表示は手動操作と共通。[WebMCP](https://developer.chrome.com/docs/modern-web-guidance/guides/webmcp/webmcp)
